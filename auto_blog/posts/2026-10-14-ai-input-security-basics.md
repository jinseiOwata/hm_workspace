生成AIを仕事で使うのが当たり前になった一方で、「どこまで入力していいのか」が曖昧なまま使っている人も多いのではないでしょうか。議事録の要約、メール文面の作成、コードのデバッグなど、便利な使い方が増えるほど、手元の資料をそのままコピー&ペーストしたくなる場面も増えていきます。しかし、その資料の中に顧客情報や社外秘の数値が含まれていないか、入力する前に一呼吸おいて確認している人はまだ多くありません。この記事では、生成AIに渡してはいけない情報の種類を具体例とともに整理し、仕事で安全に使い続けるための設定確認やプロンプトの工夫、社内ルール作りのポイントまで、今日から実践できる形でまとめます。

## この記事でわかること

- 生成AIに入力すると危険な情報の具体的な種類
- 業務シーン別のNG例・OK例
- ChatGPTなど主要サービスの「学習に使われない」設定の考え方
- 情報を守りながら使うための実践プロンプト
- 社内ルールを作るときに確認すべきチェックリスト

## なぜ生成AIへの入力に気をつける必要があるのか

生成AIチャットに入力した文章は、サービスによって扱いが異なります。無料版や個人向けプランでは、入力内容がモデルの改善(学習)に使われる設定がデフォルトになっている場合があり、設定画面からオプトアウト(学習に使わない設定)できるサービスもあります。一方、法人向けのビジネスプランやAPI経由の利用では、原則として入力データを学習に使わない契約になっていることが多いですが、これも提供元やプランによって条件が異なります。

つまり「このAIなら安全」「このAIは危険」と一律に言えるものではなく、**どのプラン・どの契約で使っているか**によってリスクが変わるということです。さらに、たとえ学習に使われない設定であっても、以下のようなリスクは残ります。

- サービス側のサーバーに一定期間データが保存される
- 社内の別部署や第三者がログを確認できる運用になっている可能性
- 入力した内容を誤って別の会話で参照・再利用してしまう人的ミス
- サービス自体の情報漏洩・不正アクセスのリスク(ゼロにはできない)

「学習に使われないから何を入力しても大丈夫」ではなく、「万が一外部に出ても困らない内容かどうか」を基準に考えるのが実践的です。

また、ブラウザの拡張機能やスマホアプリ経由で生成AIを使っている場合、公式サイト・公式アプリ以外の非公式ツールにテキストを通していないかも見落としがちなポイントです。無料で便利な拡張機能ほど、裏側でどのようにデータが扱われているか分かりにくいことがあるため、業務利用では提供元が明確なサービスを選ぶことも基本の一つです。

## 入力してはいけない情報:具体例リスト

以下は、業種を問わず注意したい代表的な情報です。自社のルールがまだない場合は、まずこのリストを社内共有するところから始めるのがおすすめです。

**1. 個人を特定できる情報(個人情報)**
氏名・住所・電話番号・メールアドレス・顔写真・社員番号などの組み合わせ。顧客リストや応募者の履歴書をそのまま貼り付けるのは避けましょう。本人の同意なく第三者サービスに個人情報を渡す行為は、個人情報保護の観点でもトラブルの原因になります。

**2. 機密性の高い社内情報**
未公開の決算数値、M&A・提携の検討情報、人事異動・評価の詳細、価格改定前の見積もり、社内規程の非公開部分など。これらが外部に漏れると、競合への情報流出や株価・取引への影響など、会社全体に関わる問題に発展しかねません。

**3. 顧客・取引先から預かった秘密情報**
契約書に秘密保持義務(NDA)がある資料、取引先から受け取った非公開の仕様書や原価情報。自社の判断だけで「大丈夫だろう」と入力してしまうと、契約違反として取引先との信頼関係を損なうリスクがあります。

**4. 認証情報・アクセス情報**
ID、パスワード、APIキー、社内システムのURLや接続情報。コードのデバッグを頼むときに、サンプルの認証情報をそのまま残しがちなので要注意です。一度入力した認証情報は、気づいた時点ですぐに無効化・再発行する運用にしておくと被害を最小限にできます。

**5. 医療・健康・信用情報などのセンシティブ情報**
病歴、健康診断結果、信用情報、犯罪歴など、特に慎重な扱いが求められる情報。人事・労務部門で扱う機会が多いため、該当部署では特に意識して注意喚起しておきたい項目です。

**6. 著作権・ライセンス上グレーな素材の丸ごと入力**
他社の非公開資料や購入した有料コンテンツをそのまま全文貼り付けて要約させる行為は、契約条件や著作権の観点でトラブルになり得ます。

**7. 法令・社内規程で外部持ち出しが禁止されている情報**
官公庁からの非公開情報、入札前の情報、監査中の内部資料など。

これらに共通するのは「もし第三者の目に触れたら、誰かが困る・不利益を被る情報かどうか」という視点です。迷ったときは、同僚や取引先に「この内容、AIに貼り付けてもいいと思う?」と一言聞いてみるだけでも、気づきにつながります。一人の感覚だけで判断しにくい場合は、上長やセキュリティ担当に確認する習慣をつけておくと安心です。

## 業務シーン別:NG例とOK例

同じ「議事録をまとめたい」という目的でも、入力の仕方次第でリスクは大きく変わります。

### 会議の議事録を要約したいとき

```
【NG例】
以下はA社との価格交渉の議事録です。要約してください。
(取引先名・具体的な値引き率・担当者氏名がそのまま含まれる文章を貼り付け)
```

```
【OK例】
以下は社外取引先との価格交渉メモです。固有名詞は
[取引先X][担当者A]のように置き換えています。
要点を3つの箇条書きで要約してください。

[取引先X]との定例ミーティング。[担当者A]より
来期の発注量について提案あり。価格帯は現行から
数%の見直しを検討中。次回までに社内で調整方針を固める。
```

### 顧客からの問い合わせメールの返信を考えたいとき

```
【NG例】
山田太郎様(住所:東京都〇〇区…、電話:090-xxxx-xxxx)
からの以下のクレームメールに返信案を作ってください。
(本文に個人情報・契約番号がそのまま含まれる)
```

```
【OK例】
以下は顧客からの問い合わせ要旨です。個人を特定できる
情報はすべて伏せています。丁寧なお詫びと今後の対応方針
を含む返信メールの下書きを作成してください。

【問い合わせ要旨】
・注文した商品が届かない(配送遅延)
・問い合わせは2回目で、前回の回答に納得していない
・返金または再送を希望している
```

議事録の例では、取引先名や担当者名、具体的な数値がそのまま残っていると、会話全体の文脈から交渉内容が特定されてしまう可能性があります。問い合わせメールの例でも、氏名や電話番号は要約や返信文の作成そのものには不要な情報です。目的に対して本当に必要な情報だけを残し、それ以外は仮の表記に置き換える、という考え方が共通しています。

### コードのエラーを直したいとき

```
【NG例】
このコードがエラーになります。直してください。
(本番環境のDB接続文字列・APIキーがハードコードされたまま)
```

```
【OK例】
このPython関数がエラーになります。認証情報部分は
ダミー値(API_KEY, DB_PASSWORDなど環境変数名)に
置き換えています。原因と修正案を教えてください。

def connect_db():
    api_key = os.environ["API_KEY"]
    password = os.environ["DB_PASSWORD"]
    ...
```

共通するポイントは、**固有名詞・個人情報・認証情報を「仮の名前」や「環境変数」に置き換えてから入力する**ことです。AIにとっては具体的な社名や氏名がなくても、構造さえ分かれば十分に役立つ回答を返してくれます。要約や文章の推敲、コードの修正といった作業の多くは、固有名詞を置き換えても精度がほとんど落ちないことも覚えておくと、置き換え作業への抵抗感が減るはずです。

逆に、固有名詞をそのまま使わないと成立しない作業(実在の取引先への提案書をそのまま清書してほしい、など)もあります。そうした場合は、個人アカウントの無料版ではなく、学習に使われないことが契約上明記された法人向けプランを使う、あるいは最終的な固有名詞の差し込みは人の手で行う、といった運用に切り替えるのが安全です。

## 安全に使うための設定確認ポイント

個別の入力内容に気をつけるのと同時に、使っているサービスの「設定」も必ず確認しましょう。確認すべき代表的なポイントは次の3つです。

1. **学習利用のオン・オフ設定があるか**
   多くの主要な生成AIサービスには、入力データをモデルの学習に使うかどうかを選べる設定項目があります。個人アカウントでも設定画面から変更できる場合があるので、業務利用の前に一度確認しておきましょう。設定項目の名称や場所はサービスのアップデートで変わることがあるため、公式のヘルプページで最新の手順を確認するのが確実です。

2. **法人向けプラン・管理コンソールの有無**
   会社としてAIを導入する場合は、個人の無料アカウントをそれぞれが使うのではなく、法人向けプランや管理者が利用状況を把握できるコンソール付きのプランを検討しましょう。利用ログの管理、メンバーの退職時のアカウント削除、データ保持期間の設定など、組織として情報を管理しやすくなります。

3. **データの保存期間・削除申請の方法**
   サービスごとに「会話履歴の保存期間」「削除をリクエストする方法」が定められています。誤って機密情報を入力してしまった場合に備えて、削除申請の手順を事前に調べておくと安心です。

これらは提供元の規約改定で内容が変わることがあるため、「導入時に一度調べて終わり」ではなく、半年〜1年に一度は最新の利用規約・プライバシーポリシーを見直す運用がおすすめです。特に無料版から法人向けプランへの切り替えを検討している場合は、料金だけでなく「データの学習利用」「保存期間」「管理者権限でできること」の3点を比較表にしてから決めると、導入後のギャップが減ります。

なお、設定項目の名称や手順はサービスのアップデートで頻繁に変わります。この記事で紹介した考え方は共通して使えますが、実際に設定を変更する際は、必ず利用中のサービスの公式ヘルプページで最新の手順を確認してから進めてください。

## 情報を守りながら使う実践プロンプト

毎回手作業で匿名化するのが面倒な場合は、AI自身に「伏せ字にしてから本題に入る」手順を踏ませる方法もあります。

```
【匿名化チェックを挟むプロンプト】
これから社内資料の要約を依頼します。
まず、私が入力する文章に個人名・会社名・電話番号・
メールアドレス・金額などの固有情報が含まれていないか
確認してください。含まれている場合は、要約作業の前に
「〇〇の部分が個人情報・固有名詞に該当する可能性があります」
と指摘してください。問題なければ要約に進んでください。

[ここに資料のテキストを貼り付け]
```

```
【社内ルール確認用プロンプト】
あなたは情報セキュリティの観点でレビューする役割です。
以下の文章を生成AIに入力することが適切かどうかを、
個人情報・機密情報・認証情報の3つの観点でチェックし、
リスクがあれば具体的にどの部分かを指摘してください。
断定的な法的判断はせず、注意点の指摘にとどめてください。

[入力予定のテキスト]
```

```
【置き換え作業を手伝わせるプロンプト】
以下の文章に含まれる会社名・個人名・金額・日付を、
[会社A][担当者B][金額X][日付Y]のような仮の表記に
置き換えた文章を作成してください。元の文章は出力せず、
置き換え後の文章だけを出してください。

[元の文章]
```

いずれのプロンプトも、最終的な判断を人間が行うための「補助」として使うのがポイントです。AIは指示通りに固有名詞を探してくれますが、見落としがゼロになるとは限りません。特に略称や社内独自のコードネーム、方言的な言い回しに含まれる個人情報は見逃されやすいため、AIのチェックを過信せず、提出前に自分の目でも確認する習慣をセットにしましょう。

## 社内ルールを作るときのチェックリスト

チームや会社でルールを整備する際は、次の項目を最低限確認しておくと抜け漏れを防ぎやすくなります。

- [ ] 利用してよい生成AIサービス・プランを明示しているか(個人の無料アカウントの業務利用を許可するかどうか)
- [ ] 入力禁止情報のリスト(個人情報・機密情報・認証情報など)を具体例つきで共有しているか
- [ ] 誤って入力してしまった場合の報告・削除申請フローを決めているか
- [ ] 顧客・取引先の情報を扱う部署には、契約上の秘密保持義務とAI利用の関係を周知しているか
- [ ] 新入社員・異動者向けに、ルールを説明する機会を設けているか
- [ ] 利用規約やプライバシーポリシーの変更を定期的にチェックする担当・頻度を決めているか

ルールは一度作って終わりではなく、サービスのアップデートや社内の利用状況に合わせて見直していくものと捉えておくとよいでしょう。特に、新しいAIツールを試験導入するタイミングでは、既存ルールがそのまま適用できるか、追加の注意点が必要かを都度確認する流れを決めておくと、運用が後手に回りにくくなります。

## まとめ

生成AIは仕事の時短に大きく貢献してくれるツールですが、便利さの裏側には「入力した情報がどう扱われるか」というリスクが常に存在します。個人情報・機密情報・認証情報など、外部に出て困るものは入力しない、もしくは固有名詞を置き換えてから使うことを基本動作にしましょう。あわせて、利用しているサービスの学習利用設定や法人向けプランの有無を確認し、個人の感覚だけに頼らずチームとしてのルールを整えておくことが、安心して生成AIを使い続けるための近道です。

一人ひとりが「この情報は入力して大丈夫だろうか」と立ち止まって考える習慣を持つこと、そしてそれをチームや会社全体のルールとして仕組み化しておくこと。この両輪がそろって初めて、生成AIを安心して時短ツールとして使いこなせるようになります。まずは今日から、入力前の一呼吸と、今回紹介したプロンプト例の活用から始めてみてください。
