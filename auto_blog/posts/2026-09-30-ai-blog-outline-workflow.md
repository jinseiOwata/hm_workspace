## この記事でわかること

- AIにブログの構成案(見出し案)を作らせる具体的な手順
- そのままコピペして使えるプロンプトテンプレート
- AIが出した構成案を「使える形」に磨き上げるブラッシュアップのコツ
- 構成案づくりでAIに情報を渡すときに気をつけたいリスク

ブログ記事を書くとき、いちばん時間がかかるのは実は「本文」ではなく「構成案づくり」だと感じたことはありませんか。何を見出しにするか、どの順番で説明するか、読者が知りたいことを漏らさず入れられているか——ここで手が止まると、記事全体の完成がどんどん遅れてしまいます。白紙のエディタを前に「まず何から書けばいいんだっけ」と手が止まってしまい、なかなか本文に進めないという経験がある方も多いのではないでしょうか。

この記事では、ChatGPTやClaudeなどの生成AIを使って、ブログ記事の構成案を効率よく作るワークフローを、実際に使えるプロンプト例つきで紹介します。AIに丸投げするのではなく、「AIに叩き台を作らせて、人が仕上げる」という現実的な分担を前提にしているので、日々の記事執筆にそのまま取り入れられます。

想定しているのは、個人ブログを運営している方や、業務でブログ・オウンドメディアの記事を書いている方です。特定のAIツールの名前や機能を暗記する必要はなく、ChatGPT・Claude・Geminiなど、普段お使いのチャット型AIであればどれでも同じ考え方で応用できます。

## AIで構成案を作るメリットと限界

まず、AIに構成案づくりを任せることのメリットと限界を整理しておきます。

メリットとして大きいのは、白紙の状態から見出し案を考える時間を大幅に減らせることです。読者が抱えていそうな疑問を洗い出し、それを見出しの形に整理する作業は、AIが得意とする分野です。キーワードや読者像を伝えるだけで、複数パターンの構成案を短時間で並べて比較検討できます。

一方で限界もあります。AIが提案する構成案は、あくまで「よくある型」に沿ったものになりやすく、そのブログならではの切り口や独自の経験談は反映されません。また、AIは事実確認をせずにもっともらしい情報を混ぜてくることがあるため、構成案の中に出てくる数字や固有名詞、統計データなどは鵜呑みにせず、自分で裏を取る必要があります。あくまで「たたき台」として使い、最終的な取捨選択や独自性の追加は人間の役割だと考えておくと失敗しません。

言い換えると、AIは「読者が知りたそうなことを漏れなく洗い出す」作業や「見出しの言い回しを整える」作業には強い一方で、「このブログでしか読めない一次情報を作り出す」ことはできません。この役割分担を意識しておくと、AIに何をどこまで任せるべきかの判断がぶれなくなります。

## 事前準備:AIに渡す情報を整理する

AIに良い構成案を作ってもらうためには、丸投げする前の準備が重要です。以下の4つを事前にメモしておきましょう。

1. **記事のテーマとゴール**:何についての記事で、読者にどんな行動を取ってほしいのか
2. **想定読者**:初心者向けか、ある程度知識がある人向けか
3. **狙いたい検索キーワード**:読者がどんな言葉で検索してこの記事にたどり着くか
4. **記事の分量の目安**:見出しの数や本文全体の長さの希望

例えば、この記事自体を作るときであれば「AIでブログの構成案を作る手順を知りたい、AIツールに詳しくないブログ初心者」を想定読者に設定し、「AI 構成案 作り方」のようなキーワードを狙いたい、といった具合にメモを作っておきます。この程度の粒度で十分です。

これらをメモ帳などに一度書き出しておくと、AIへのプロンプトを組み立てるときにそのまま使えます。逆にここが曖昧なまま「いい感じの構成案ちょうだい」と頼むと、抽象的で使いにくい構成案が返ってきがちです。

さらに余裕があれば、「参考にしたい既存記事のURLやタイトル」「入れたくない内容(すでに他の記事で書いた話など)」もメモしておくと、AIとのやり取りの回数を減らせます。準備を丁寧にしておくほど、後から何度もやり取りをやり直す手間が減っていく感覚があります。

## 実践ワークフロー:AIで構成案を作る5ステップ

ここからは、実際にAIとやり取りしながら構成案を仕上げていく手順を、5つのステップに分けて説明します。

### ステップ1:テーマとゴールを伝えて骨子を出させる

まずは大枠の骨子を出してもらいます。細かい指定をしすぎず、ざっくりとしたテーマとゴールだけを伝えるのがポイントです。最初から完璧な指示を書こうとせず、6〜7割の情報を渡していったん出してもらい、足りない部分は次のステップ以降で補っていくくらいの感覚で進めると気が楽です。

```
あなたはSEOとブログ編集の経験が豊富な編集者です。
以下の条件でブログ記事の構成案(見出し案)を作ってください。

テーマ:[記事のテーマを入力]
想定読者:[例:AI初心者の会社員]
狙いたい検索キーワード:[キーワードを入力]
記事の目的:[例:読者に○○を実践してもらう]

条件:
- 見出しは大見出し(##)6〜8個程度
- 各見出しの下に、書く内容を1〜2行で要約
- 読者が知りたいであろう疑問を漏らさない構成にする
```

このプロンプトを送ると、たとえば「在宅ワークの集中力が続かない理由」というテーマの場合、以下のような形で返ってくるイメージです。

```
## 在宅ワークで集中力が続かない主な原因
・要約:環境音、通知、家事の誘惑などを整理して紹介

## 作業前に整えておきたい環境づくり
・要約:デスク周り、通知設定、家族との取り決めなど

## 集中力を保つための時間の区切り方
・要約:ポモドーロ・テクニックなど具体的な時間管理法

## それでも集中できないときの対処法
・要約:場所を変える、軽い運動を挟むなどの応急対応

## まとめ
```

このように、見出しと要約がセットで返ってくれば十分です。この時点ではまだ粗さがあって当然なので、「悪くはないけど、もう一声」くらいの温度感で受け止めておきましょう。

### ステップ2:読者の疑問を洗い出させる

骨子だけだと網羅性が不安なので、読者が持ちそうな疑問をリストアップさせ、構成案に漏れがないか確認します。この一手間を入れるだけで、「そういえばこの疑問には答えていなかった」という抜け漏れにその場で気づけます。

```
先ほどの構成案のテーマについて、
読者が検索する前後に抱いていそうな疑問を10個挙げてください。
その上で、先ほどの構成案でカバーできていない疑問があれば
指摘してください。
```

### ステップ3:複数パターンを比較する

1つの構成案だけで決め打ちせず、切り口の違う案を並べて比較すると、より読者に刺さる構成が見つかりやすくなります。特に「手順を知りたい読者」と「失敗を避けたい読者」では響く見出しの立て方が変わるため、両方の切り口を見比べてから選ぶだけで、記事の刺さり方が変わってきます。

```
同じテーマで、切り口が異なる構成案をあと2パターン考えてください。
パターンA:実践手順を軸にした構成
パターンB:よくある失敗・注意点を軸にした構成
それぞれの見出し案と、どんな読者に向いているかを教えてください。
```

### ステップ4:自分の経験・データを足す指示を出す

AI任せの構成案は「よくある一般論」になりがちなので、自分の体験や社内データを反映させる指示を追加します。ここで差し込む一次情報こそが、検索結果に並ぶ他の記事との違いになる部分です。面倒でも、自分にしか書けないエピソードを1つは見出しに組み込んでおくことをおすすめします。

```
先ほどの構成案に、以下の実体験・データを反映した見出しを
1〜2個追加してください。

・実体験や事例:[自分の体験を入力]
・伝えたい独自の主張や視点:[入力]
```

### ステップ5:見出しごとの文字数配分を決める

最後に、記事全体の分量に合わせて、各見出しにどのくらいの文字数を割り振るかを決めてもらいます。ここまで来ると、あとは各見出しに沿って本文を書くだけの状態になります。

```
この構成案について、記事全体を[目安の文字数]字に収める前提で、
各見出しの文字数配分の目安を提案してください。
```

ここまでの5ステップは、慣れてくると1つのチャットの中で連続して指示を出すだけで完結します。最初は少し手間に感じるかもしれませんが、テンプレート化してしまえば、次回以降はテーマとキーワードを差し替えるだけで同じ流れを再現できます。

## そのまま使えるプロンプトテンプレート集

上記のワークフローで使ったプロンプトのうち、特に汎用性が高いものを4つまとめておきます。テーマやキーワードの部分だけ書き換えれば、さまざまな記事で使い回せます。

**テンプレート1:骨子出し用**

```
[テーマ]についてのブログ記事の構成案を、
##見出し6〜8個、各見出しの要約1〜2行つきで作成してください。
想定読者は[読者像]、狙いたいキーワードは[キーワード]です。
```

新しい記事に着手するとき、最初の一手として使うテンプレートです。何も決まっていない状態からでも、ここから会話を広げていけます。

**テンプレート2:網羅性チェック用**

```
[テーマ]について検索する読者が抱く疑問を10個挙げ、
以下の構成案でカバーできていない疑問を指摘してください。
[構成案を貼り付け]
```

骨子ができた直後、見出しの抜け漏れがないか不安なときに使います。他の人が書いた構成案のレビューにも応用できます。

**テンプレート3:リライト・改善用**

```
以下の構成案を、[改善したい方向性:例 初心者にもっと分かりやすく]
という観点で見直し、変更点とその理由をセットで提案してください。
[構成案を貼り付け]
```

一度作った構成案を、ターゲット読者を変えて作り直したいときや、方向性を修正したいときに使います。

**テンプレート4:見出し文言のブラッシュアップ用**

```
以下の見出し案を、検索している読者が思わずクリックしたくなる
表現に言い換えてください。誇張表現は避け、内容と一致する範囲で
お願いします。
[見出し案を貼り付け]
```

内容は固まったものの、見出しの言葉選びがありきたりに感じるときの仕上げ用です。「誇張表現は避け」と明記しておくと、内容と乖離した煽り気味の見出しになるのを防げます。

## AIの構成案をブラッシュアップするコツ

AIが出してきた構成案は、そのまま使うのではなく、次の3つの視点でチェックすると記事の質がぐっと上がります。

1つ目は「見出しの重複・冗長さの確認」です。AIは似たような内容の見出しを別々に提案してくることがあるため、統合できる部分がないか見直しましょう。

2つ目は「独自性の追加」です。前述の通り、AIの提案は一般論に寄りがちなので、自分だけの経験談や具体的な数値、失敗談などを1つでも入れると、他の記事との差別化になります。

3つ目は「検索意図とのズレのチェック」です。狙っているキーワードで実際に検索してみて、上位に出てくる記事と見出しの粒度が大きくズレていないかを確認すると、読者の期待に応えやすい構成になります。

この3つは、慣れないうちはチェックリストとして手元にメモしておき、構成案が仕上がるたびに一つずつ確認していくと、抜け漏れなく見直せます。

## 情報入力時に気をつけたいリスク

構成案づくりでAIとやり取りする際、次の点には特に注意してください。

- **個人情報・機密情報を入力しない**:社内の未公開データ、顧客情報、取引先の名前などは、たとえ構成案づくりのメモとしてでも入力しないようにしましょう。多くのAIサービスでは入力内容が学習や記録に使われる可能性があるため、公開されて困る情報は避けるのが安全です。会社で使う場合は、事前に自社のAI利用ガイドラインがあるかどうかも確認しておくと安心です。
- **AIが出す情報を事実確認なしに使わない**:構成案の中にAIが独自に付け加えた統計データや事例が混ざっていることがあります。裏取りできない数字や固有名詞は、そのまま本文に使わないようにしましょう。特に「〇〇によると」といった出典つきの情報は、実在するかどうかを自分の目で確認してから使うことが大切です。
- **著作権・引用のルールを守る**:他サイトの文章をそのまま構成案や本文に流用するのは避け、参考にした情報は自分の言葉で書き直すか、引用のルールに従って明記しましょう。AIに「他サイトのような文章にして」と頼むこと自体が、意図せず表現の丸写しにつながる場合もあるため注意が必要です。
- **利用規約・料金プランは最新情報を都度確認する**:AIサービスの機能や料金プランは変更されることがあるため、記事に反映する際は必ず公式サイトなど最新の情報源を確認してください。

これらを守った上でAIを活用すれば、構成案づくりの負担を減らしながら、記事の質を保つことができます。リスクを避けることと、AIを使いこなすことは、決して矛盾するものではありません。

## まとめ

AIを使ったブログ構成案づくりは、「骨子出し→疑問の洗い出し→複数パターン比較→独自性の追加→文字数配分」という5ステップのワークフローに落とし込むことで、迷いなく進められるようになります。ポイントは、AIに丸投げするのではなく、テーマや読者像といった前提情報をきちんと渡し、出てきた構成案を人間の目でブラッシュアップすることです。

また、構成案づくりの段階から、個人情報や機密情報を入力しない、AIの出す情報を鵜呑みにしないといったリスク管理を意識しておくと、安心して日々の執筆にAIを取り入れられます。

最初は本文を書くよりも構成案づくりに時間をかけるくらいの気持ちで、AIとのやり取りを重ねてみてください。骨組みさえしっかり固まっていれば、本文執筆のスピードも自然と上がっていきます。今日紹介したプロンプトテンプレートをコピーして、次の記事の構成案づくりからさっそく試してみてください。
